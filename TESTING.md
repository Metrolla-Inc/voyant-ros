# Tests (Metrolla)

Three tiers, separately named jobs in `.github/workflows/ci.yml`. `.github/workflows/docker-image.yml`
builds the image for amd64 on pull requests (not pushed; arm64 cannot link, docs/VENDOR_DIFF.md); `vendor-watch-tests.yml` tests
the weekly vendor comparison separately. The vendor's pre-commit hooks (`.pre-commit-config.yaml`)
are not run in CI.

| Tier | Command | What it proves |
|---|---|---|
| unit | `python -m pytest tests/unit tests/legacy` (+ shellcheck, hadolint in CI) | the contract (docker/voyant_env.py): every variable, default and refusal, model names (`carbon`; the Carbon Dev Kit's names refused), the HOST_IP route lookup, `SENSOR_IP` reaching the client (`fpga_target_address`), `TIME_MODE` sensor/host, the rendered parameters file, the exec line, the run/check/selfcheck commands, and that the parameters it sets are exactly the ones `src/sensor_driver.cpp` declares; the image workflow's tag step run with bash (only `v<vendor version>-metrolla.<n>` tags, from the tagged commit); the legacy entrypoint is the released command behind the opt-in block |
| regression | `python -m pytest tests/regression tests/legacy` (needs the git history: the past-bug tests read main 7e6f9aa, the vendor's v1.0.1 ef121af and main 1061d30) | goldens: the released command's record (what it prints, sources and starts, with which environment) for 8 environments (image default, repo and datablade compose, switch 0/empty, contract names without the switch, operator command, VIZ_BRIDGE_ARG=true), from the released Dockerfile (`tests/legacy/Dockerfile-released`, git blob pinned), which `docker/voyant_entrypoint.sh` must reproduce; the launch file is the released one and `config/sensor_params.yaml` the vendor's v1.0.1 one (blobs pinned); contract `check` and `check --json` output for 18 environments (accepted and refused, including the Carbon Dev Kit); past bugs, each failing on the files that had it: SIGTERM not bound, first-frame wait deaf to shutdown, errors exiting 0, spin after SIGINT (released files and the vendor's v1.0.1), voyant-api taken unpinned from "latest", Cap'n Proto unchecked, images for branches / mutable cache tags / overwritable tags / no digest, unpinned actions, an arm64 image that cannot link, the Carbon refused with the Dev Kit named instead (main 1061d30), `SENSOR_IP` never reaching the client (the vendor's v1.0.1 node) |
| smoke | `docker/smoke/smoke.sh IMAGE` (needs Docker and python3) | the real image: entrypoint, no command, root, voyant-api 1.0.1 with Voyant's notices, the Carbon simulator present; the released shell-form ENTRYPOINT, built by Docker from the released lines, is exactly the command the new entrypoint runs; against voyant-api 1.0.1's own Carbon simulator (`voyant_simulator`: 23,168 points, 10 Hz, multicast, answering on its FPGA register port) and a reference receiver built in the image from the same SDK (`docker/smoke/frame_dump.cpp`, CarbonClient as an observer): legacy mode (vendor parameters, on a Docker network with the simulator at 192.168.1.128) publishes `/point_cloud` frame `voyant_sensor`, every cloud one reference frame point for point, frame-time stamps, metadata; contract `check` and refusals byte-identical to the goldens; contract as uid 97000, read-only root, tmpfs /tmp, cap-drop ALL, no-new-privileges, host network and IPC, the simulated sensor at 127.0.0.2: PID 1 is the node with the rendered parameters, clouds on the contract's topic and frame matching the reference, `TIME_MODE` sensor stamps equal to the frames' own times and `host` stamps the host's clock, device metadata (voyant-api 1.0.1), the client reaching the sensor at `SENSOR_IP`, invalid points dropped, four `docker stop` and one SIGINT under load with exit 0 in under 5 s, `docker stop` with no sensor exit 0 at once and idle CPU while waiting, a port held by another process exit 1 |

Run the Python tiers locally: `python -m venv .venv && .venv/bin/pip install pytest==9.0.1
pyyaml==6.0.3`, then the commands above. `REGEN=1` rewrites goldens (legacy ones only from the
released command, never from the current script).
